# Участие в проекте

Баг-репорты, идеи и пул-реквесты приветствуются. Английская версия README - [README.en.md](README.en.md); общаться в issues и пул-реквестах можно по-русски и по-английски.

## Сообщить об ошибке или предложить идею

Откройте [issue](https://github.com/SergeyShk/ruTS-adapt/issues/new/choose) по шаблону. Для ошибки нужны команда с аргументами и текст, на котором она воспроизводится, ожидаемый и фактический результат, версии ruTS-adapt, Python и ОС. Для идеи - какой текст и для какого читателя нужно адаптировать и почему текущей команды не хватает.

Уровень текста измеряет библиотека [ruTS](https://github.com/SergeyShk/ruTS): ошибки в значениях метрик удобочитаемости и новые метрики обсуждаются в её репозитории.

## Окружение разработки

Проект использует [uv](https://docs.astral.sh/uv/) для управления зависимостями и [ruff](https://docs.astral.sh/ruff/) для линтинга и форматирования. Требуется Python 3.11 или новее.

```bash
git clone https://github.com/SergeyShk/ruTS-adapt.git
cd ruTS-adapt

make deps                   # создать окружение и установить все зависимости
uv run pre-commit install   # хуки: линтеры на коммите, тесты на пуше
```

Полный список команд - `make help`.

## Проверки

Перед отправкой пул-реквеста должны проходить:

```bash
make lint        # ruff check --fix, ruff format, mypy
make test-cov    # pytest: тесты и примеры из докстрингов (doctest) с порогом покрытия
```

То же самое выполняет CI на Python 3.11-3.14 (Linux), а также на Windows и macOS для одной версии Python.

Тесты и CI не обращаются к API моделей: код, который вызывает модель, получает модель чата LangChain параметром, а тесты подставляют поддельную модель с заранее заданными ответами в форме ответов Anthropic, OpenAI и Gemini. Тесты, которым нужна настоящая модель, помечаются `@pytest.mark.llm` и по умолчанию не запускаются; запуск вручную, с ключом провайдера в окружении (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` или `GOOGLE_API_KEY`) - `uv run pytest -m llm`.

## Что ожидается в пул-реквесте

- **Одна тема - один пул-реквест.** Правки не по теме лучше вынести отдельно.
- **Тесты.** Новый код покрыт тестами в `tests/` (структура повторяет пакет), покрытие - 100 % без тестов с маркером `llm`.
- **Документация.** Изменения в README вносятся в обе версии: `README.md` и `README.en.md`. Примеры в докстрингах показывают фактический вывод.
- **Совместимость.** Изменение команды - параметров, формата вывода - только с пояснением в описании пул-реквеста: оно попадёт в заметки релиза.
- **Стиль.** Код форматируется ruff (`make format`), типы проверяются mypy, докстринги на русском в принятом в проекте формате (`Описание`, `Аргументы`, `Вывод`, `Исключения`). Промпты модели, справка команды, предупреждения и сообщения об ошибках - тоже на русском, имена в коде - на английском. Комментарии в коде не дублируют то, что видно из него самого.
- **Коммиты.** Сообщения на русском в повелительном наклонении: «Добавить …», «Исправить …», «Убрать …».

Описание пул-реквеста отвечает на два вопроса: что сделано и почему. Если пул-реквест закрывает issue, укажите его номер.

## Как устроен репозиторий

- `ruts_adapt/` - пакет команды.
- `tests/` - тесты, повторяющие структуру пакета.
- `.github/workflows/ci.yml` - CI.

Пакет не публикуется в PyPI и запускается из клона репозитория. Версия хранится только в `pyproject.toml`; релизы выпускаются тегом и GitHub Release, изменения описываются в его заметках, отдельного файла CHANGELOG нет.
